1. Executive Summary
This document outlines the plan to implement a dual-template system for both Report Cards and the Gradebook within Graviton CMS. The system will automatically detect whether a student belongs to the Nursery/Primary level or the Secondary level (JSS/SSS) and render the appropriate template with a tailored design, grading scale, and layout.
The goal is to provide age-appropriate, visually distinct academic reports that meet the expectations of parents, students, and regulatory standards for each educational level.
Key Benefits:
Age-appropriate presentation of academic results
Different grading scales per level (descriptive vs. numeric)
Customizable column layouts for each level
Single codebase with template branching — no data duplication
Admin-configurable template settings via the Settings panel

3. Proposed Architecture
3.1 Template Selection Flow
The system will use a simple decision tree based on the student's class level:
Step 1: User requests a report card or opens the gradebook for a student/class.
Step 2: System looks up the class record from the classes table.
Step 3: The class.level field is checked (e.g., "Nursery", "Primary", "JSS", "SSS").
Step 4: If level is "Nursery" or "Primary" → Template A (Nursery/Primary) is used.
Step 5: If level is "JSS" or "SSS" or "Secondary" → Template B (Secondary) is used.
Step 6: The appropriate template renders using the same underlying score data.
3.2 Configuration Architecture
Template behaviour will be configurable via the Admin Settings panel. A new settings key report_card_config will store a JSON object with per-level settings:

4.3 Template Switching Logic
The template switching is determined at render time using the class level. The pseudocode below illustrates the branching logic:
function generateReportCard(student, term, session) {    const classRecord = getClass(student.class_name);    const level = classRecord.level;  // "Nursery", "Primary", "JSS", "SSS"        const isNurseryPrimary = ["Nursery", "Primary"].includes(level);        if (isNurseryPrimary) {        return renderNurseryPrimaryReport(student, term, session);    } else {        return renderSecondaryReport(student, term, session);    }}

7. Implementation Phases
Phase 1: Configuration & Settings (1–2 days)
Create the report_card_config settings key with default JSON values
Add a "Report Card Settings" section in the Admin Settings panel
Build UI for admins to customise grading scales, column visibility, and trait lists per level
Add level detection helper function: getTemplateType(className)
Phase 2: Gradebook Branching (2–3 days)
Refactor the existing gradebook renderer to accept a template configuration object
Create the simplified nursery/primary gradebook view (2-column CA input)
Preserve the existing secondary gradebook view (5-column CA input)
Add level-based branching at the point where the gradebook is rendered
Ensure score saving works correctly regardless of which columns are visible
Test data integrity: scores saved from simplified view load correctly in full view
Phase 3: Report Card Templates (3–5 days)
Design and build the Nursery/Primary HTML report card template
Add behavioural traits and psychomotor skills sections with 1-5 rating inputs
Design and build the Secondary HTML report card template with WAEC grading
Add class position, percentage, and summary statistics to secondary template
Implement template switching logic in the report card generator
Add print-optimised CSS for both templates (A4 portrait)
Implement PDF export for both templates
Phase 4: Testing & Polish (1–2 days)
Test with real data across all class levels
Verify offline report card generation works for both templates
Test print output quality on physical printers
Gather feedback from teachers and admin users
Fix edge cases (students changing levels mid-session, empty score handling)
Estimated Total Duration: 7–12 working days

10. Testing & Verification Plan
10.1 Functional Tests
Open gradebook for a Nursery class → should show 2-column (CA + Exam) layout
Open gradebook for a JSS class → should show 5-column layout

Change a class from Primary to JSS → verify template switches on next report generation
Test with a student who has no scores → verify graceful empty state for both templates
10.2 Offline Tests
Generate nursery/primary report card while offline → should work from IndexedDB data
Generate secondary report card while offline → should work from IndexedDB data
Open gradebook while offline → correct template should render based on cached class data
10.3 Edge Case Tests

Admin changes grading scale in settings → new reports reflect updated scale immediately
